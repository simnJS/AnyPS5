### What
Every staged region of a cached build keeps two device-local buffers: its shadow, and the snapshot the changed-byte copy-back compares the shader's stores against. The snapshot is only read between the copy-in and the copy-back of one use, and no descriptor names it. It stayed with the build anyway, so half of the device memory held by staging grew with the build cache. That growth is what #18356 bounds.

The region now keeps a weak reference once its copy-back is recorded:
- A use recorded while an earlier batch still holds the snapshot takes the same one, exactly as before.
- Once no batch holds it, the buffer returns to the buffer pool's device tier, and the next use takes one from there.

Nothing changes in what is copied or stored.

This composes with #18356 (a local merge is clean): under its bound, the snapshots no longer count against the limit while idle, so about twice as many regions can stay staged.
