### What
The stamp that lets a captured image table be reused without reading its words again (`ShaderMemory::stampWrites` / `Vouched`) recorded the registry generation. That generation moves on every guest allocation, release, map and protection change. A title that allocates every frame therefore lost the unwritten reuse every frame, and compared or rebuilt each table instead.

The stamp now records the forget serial, and a vouch asks whether the table's own range was forgotten since. This is what #16879 does for draw input snapshots; this PR uses its unconditional invalidator and its range reports for image registration.

- A range registered or removed elsewhere keeps the stamp.
- A mapping change over the table still ends it.

Not changed: the image-view identity (`normalizeImageView`) and `CurrentTableState` still follow the registry generation. It is recorded in the debt file.

Three existing tests encoded the old contract and were updated:
- `table snapshot reuse` and `table vouch` expected a range registered elsewhere to end the reuse. They now expect it to be kept, and an invalidation of the table's own first page to end it.
- `agc_driver_image_table_vouch_queued_draws` built its stamp by hand from the registry generation; it now uses the forget serial.

  - The validation layer was found in both runs. Both logs hold that same VUID 27 times and no other.
- Negative control: with the old stamp, the updated `table snapshot reuse` test fails with `the table after a range was registered elsewhere: an unwritten table was read again`.
- One case I could not explain: in the `table edge store` setup (a table with an unwatched tail), a range registered and removed elsewhere still ended the vouch on this branch, although the mapping check passed. I did not find which other check refuses it, so that configuration may not gain.
