### What
`Arc.cpp` ports `src/cairo-arc.c` and the major-axis helper of `src/cairo-matrix.c` from Cairo 1.18.0, as asked on #15679. It is a separate file with the full upstream notice and a `Derived from` line.

- Angles are normalized as `cairo_arc` and `cairo_arc_negative` do.
- Arcs longer than pi are split.
- The number of Bezier segments follows the CTM major axis at the default 0.1 tolerance. The catalogue has no `cairo_set_tolerance`.
- A radius of zero or less adds the centre twice.
- Infinite or NaN angles stop after the first line, as in Cairo.

`cairo_curve_to` now follows `_cairo_path_fixed_curve_to`:
- It drops a preceding degenerate line. Every arc that starts from no current point produces one; without this the path was `M L C` where Cairo gives `M C`.
- A curve that does not move is tested against the last path point before the implicit move. That point survives `cairo_new_sub_path` and is the origin after `cairo_new_path`. Before, `curve_to(5,5,5,5,5,5)` on an empty path gave `M L` where Cairo gives `M C`.

Overlap: #18381 implements `cairo_rectangle`, the operator state and `cairo_path_extents`. This PR implements none of those exports; it edits the same `Export.cpp`, `InventoryExports.hpp`, CMake and debt lines, so whichever lands second needs a merge of `main`.

### Tested
- Linux (Ubuntu 24.04, GCC 13, Release): the 9 `guest_cairo_*` tests pass. `guest_cairo_arc` also passed under ASan and UBSan on an earlier stack of this change.
- `guest_cairo_arc` compares 17 arc cases and 9 degenerate-curve cases with the element streams the host's Cairo 1.18.0 gives for the same calls. The comparison is exact except for the non-dyadic scaled and the rotated CTMs (1e-12).
- It also checks a 70000-turn arc (262144 curves, clamped to 65536 full circles) against Cairo's element count and endpoints.
- 20000 arcs at extreme scales and radii, run against the host's Cairo: no difference.
- Not run on Windows.
