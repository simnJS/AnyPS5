### What
Implements `cairo_rectangle`, `cairo_set_operator`, `cairo_get_operator` and `cairo_path_extents` following Cairo 1.18.0.

- `cairo_rectangle` is `_cairo_default_context_rectangle`: a move, three relative lines, then a close. The relative distances are converted with Cairo's unclamped fixed-point conversion and added as 32-bit numbers, so a huge size wraps and an infinite one adds nothing, as in Cairo.
- `cairo_close_path` now adds and drops the closing line like `_cairo_path_fixed_close_path`. So a rectangle with a zero or sub-1/256 height gives `M L Z M`, and `M L L(back to start) Z` drops the last line. The previous close kept it.
- The operator is stored without validation in the saved graphics state. It is OVER (2) by default and on an errored context.
- `cairo_path_extents` bounds the applied points in device space: a lone trailing move does not count, and curves add their extrema through a port of `_cairo_spline_bound`. That port is in `Spline.cpp`, with the Cairo notice and a `Derived from` line. The box is mapped back through the inverse CTM and device scale. Every non-null output is written, with zeros for an empty path, an errored context or a null context.
- Path coordinates no longer keep a negative zero, which `cairo_path_extents` returned where Cairo returns zero.

The PRs closed earlier for these exports (#15430, #15675) had review points, which this PR handles:
- the test checks the exact element stream and every corner, not just the extents;
- zero and near-zero heights are compared with Cairo's own output;
- `cairo_path_extents` writes each non-null pointer.

Gaps recorded in the debt file:
- last-bit differences under a rotation or a device scale;
- a device scale of zero throws in `cairo_path_extents`;
- non-finite coordinates and the line-width margin of Cairo's coordinate clamp are not followed by the path exports. Both existed before this PR.

### Tested
- Linux (Ubuntu 24.04, GCC 13, Release): all `guest_cairo_*` tests and the 65 `public_headers*` tests pass. The touched tests also pass under ASan and UBSan.
- The expected values in `guest_cairo_rectangle_extents` come from the host's Cairo 1.18.0, with the same calls run natively. They are compared exactly, sign of zero included, except for one rotated CTM, which uses a 1e-12 tolerance. Cases include huge, wrapping and infinite sizes.
- 20000 random sequences of move, line, curve, close, rectangle, arc, new sub-path and append under random CTMs and device scales, run against the host's Cairo with the three branches together: 5 differ, all in the last bits of a recomputed inverse.
- Negative controls: putting back the previous `cairo_close_path`, or flipping the rectangle's height, fails the test.
- Not run on Windows.
